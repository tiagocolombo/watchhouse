# Datadog monitor polling v1

`datadog --file CONFIG --operator NAME` installs an immutable, consecutively numbered profile. Profiles retain exact input source, installer and timestamp. The versioned [synthetic configuration](../../../tests/fixtures/datadog/config.json) maps each monitor ID to an explicit service/environment/repository, an allowlisted Datadog site, dedicated API/application credential references, bounded refresh/request budgets and independent severity/update timers. Profiles cannot be installed through model or web commands. No source mapping authorizes repository repair, merge or production mutation.

`datadog-sync` performs one due read; `serve` and continuous `worker` also poll independently of models. A durable per-monitor reservation rotates its next scheduled time before I/O. Failed monitors cannot monopolize the queue, and downtime/restart resumes periodic current-state reconciliation. Concurrent reads/configuration changes are fenced by exact profile revision and generation. Stable source/case identities preserve records across reconfiguration; removed mappings invalidate context immediately. Each provider has its own configuration and read ledger, avoiding collisions between numeric revision IDs.

Native transport uses only authenticated `GET https://api.SITE/api/v1/monitor/ID?with_downtimes=false`, with redirects/proxies disabled, bounded time/output and no provider-returned URL traversal. API errors or malformed/foreign responses become unavailable read health. They do not manufacture a healthy observation or a monitor case. Authorization/authentication details never appear in error prose. Current monitor responses retain only ID, name and recognized overall state; query, message, tags, users and arbitrary extensions are excluded.

The normalized v1 source record keeps legacy wire field names `signal.issue_id` and `signal.project_id` for compatibility: for this adapter they contain the external monitor ID and configured stream/profile ID. This is not Sentry issue semantics. `source_key` has the independent namespace `datadog:PROFILE/MONITOR`. `count`, release, deployed revision and diagnostic event context stay unknown. Timestamp means snapshot collection time, not failure onset. Unchanged polls refresh read health without adding fact/event noise. A later `OK` monitor state does not resolve a response.

This adapter deliberately uses polling intake. It does not advertise webhook delivery, historical transition reconstruction, monitor discovery outside the explicit allowlist, full error events, metrics/request denominators or deployment lookup. A brief transition that begins and ends while offline may be missed; coverage never claims otherwise. Unsupported capabilities are visible in status. Broader configured Datadog capabilities require their own separately implemented adapters, not fabricated equivalence.

`datadog-status` and authenticated `GET /api/v1/sources/datadog` expose profiles/provenance, credential-presence booleans, per-monitor read state and capability limits. The web coverage panel uses the same records. Common incident declaration/update, recovery, source context, correlation and repair gates consume mapped facts without provider-specific domain policy. A changed mapping invalidates candidate/knowledge/impact/recovery context even before another provider read. Recovery and impact supervision use the common source validity projection.

Fixtures cover independent revision namespaces, current-state intake, deduplication, missed current-state change/restart, fair outages, late overlapping/configuration-changed reads, foreign payloads, no-count/no-recovery semantics, omitted untrusted fields, transactional projection rollback and incident timers without a Sentry installation. These are injected API/controller fixtures; no live Datadog account, credentials, monitor or operational history was exercised. Activation requires explicit real mappings, appropriately scoped API/application keys, network access and sanitized history. The configured OS operator owns missing credentials and coverage review.
