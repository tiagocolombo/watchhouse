# Local fake-team v1 commands

Executable shapes are [domain/team.rs](../../../src/domain/team.rs). New examples are strict v1 fixtures: [message](message.json), [block](block.json), [handoff](handoff.json), [accept](accept.json), [finish](finish.json). Replace example versions/IDs and run proofs with actual returned values. No real runtime, remote worker identity, or external notification channel is admitted.

Operator commands use `command: {meta, expected_version}`. Meta contains schema_version, idempotency_key, actor, and reason. PostMessage additionally requires kind/body/recipients/evidence_refs/reply_to/ack_within_seconds. Only observation/question/status can be posted directly; block/handoff messages are generated by their dedicated transitions. Evidence stays in the case; replies stay in its thread and are limited to depth 8. Messages support 1..5 distinct local recipients, 8000-byte text, and optional acknowledgment within 1..86400 seconds. AcknowledgeMessage supplies message_id and requires a listed recipient; acknowledgment does not resolve an escalation or transfer ownership.

ClaimWork uses `{meta, executor}`; no work returns null, and retrying the same key returns its original response (even null). A successful claim returns Claim with schema_version, job_id, case_id, run_id, fence, executor, task, and a frozen Briefing. Initial `run.started` records acceptance. RunCommand uses `{meta, proof:{run_id,fence}}`; actor must match the recorded executor. Heartbeats and progress use current unexpired run authority instead of a case version, so unrelated messages cannot invalidate a healthy worker. ReportProgress adds checkpoint/evidence_refs under `{run,...}` and requires a new content digest; identical content under another key does not reset progress. This is reported synthetic progress, not independently verified experimentation.

ReportBlock uses `{run, details}`: reason_code (missing_evidence or missing_capability), work_attempted, last_useful_progress, checkpoint, assistance_needed, uncertainty, and at most 19 case evidence references. The system adds an immutable checkpoint, accountable case owner, response deadline, and local-operator-inbox escalation path, then revokes the attempt. Supervisor timeout reasons cannot be asserted through the worker command.

OfferHandoff supplies block_id, successor, next_owner, acknowledge_within_seconds (1..120). It freezes objective/role/checkpoint, evidence refs, the most recent 20 relevant message IDs, prior run, original assignment deadline, and remaining attempts. Only local fake-* executor identities are admitted, all with the same side-effect-free investigator capability. AcceptHandoff supplies handoff_id; the addressed successor must accept while the offer is current and within its acknowledgment/deadline/attempt budget. A new attempt/fence and ownership transfer commit together. Nothing transfers on offer alone. A fake worker process discovers its addressed offers automatically.

Development fake limits are a 30-second lease, 60-second progress deadline, 120-second block response window, 300-second assignment wall time, and three total attempts; migrated active histories retain at least one remaining attempt. Heartbeats/progress/handoffs cannot extend the original absolute deadline. A unique reported checkpoint is necessary but does not prove semantic useful progress. Policy configuration and semantic repetition detection remain later M2 work. All deadlines use the injected clock and survive restart.

`team finish` simulates a result from the stored objective and proof. A late known proof retains wrapped unaccepted output by run/digest once and returns conflict. Accepted results and late artifacts have distinct provenance; a stale attempt cannot update assignment/case outcome. Audit history/version can advance to record the rejection. Unknown/misattributed proofs are rejected without inventing provenance.

Escalations are durable local inbox records, not claims of external delivery. Source uniqueness prevents duplicate overdue records. AcknowledgeEscalation supplies escalation_id and must use the local inbox owner (`operator`). Acknowledgment remains distinct from resolution; no resolution or fallback notification chain is implemented yet. A handoff does not silently dismiss older escalations.

Snapshot adds `team` with control, threads/messages, runs, blocks, handoffs, escalations, and late result references. No run fence is included in the ordinary snapshot. Legacy Case/Assignment execution states remain unchanged; control carries queued/running/blocked/handoff_pending/completed coordination state. Block history can be open/handoff_pending/escalated/transferred, and handoffs proposed/accepted/expired. Transferred is not a claim that the original blocker or service is fixed.

All team methods are shared Rust Application services used by CLI and authenticated local HTTP. The local bearer operator can simulate executor attribution; this is not a worker authentication/RBAC protocol. Do not connect a real harness to these fake control surfaces.
