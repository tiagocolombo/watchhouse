# Claude Code text roles v1

The existing `model-policy`, `case request-model`, `model-worker`, adoption and cancellation/reconciliation commands accept an independently installed Claude profile. Set `adapter: "claude_code"`, an explicit `profile` ID (for example `reviewer`), exact full `requested_model`, the pinned native **Claude Code 2.1.329** binary and the existing pinned initializer/cgroup/job-root/resource fields. Use `authority: { "type": "claude_api_key_env", "token_env": "WATCHHOUSE_CLAUDE_REVIEW_KEY" }` for explicit live API-key use, or `authority: { "type": "fixture" }` for synthetic roles. No model/web command installs policy or supplies credential values.

This fixed adapter launches bare/restricted print mode with an empty built-in tool set, all tools denied, empty strict MCP configuration, no slash commands, no saved session, no settings sources, a single turn and clean environment. Briefing/schema data goes through stdin; no candidate program executes in this credential domain. Only known built-in metadata from the pinned runtime is allowed. Init capability drift, external plugins/agents/skills/MCP, tool content, denied permissions, spawned subagents, changed session IDs, unsupported/error terminals or rewritten final text reject output. Actual model and harness-reported usage are retained; model aliases/fallbacks that differ from the requested exact model are not accepted. Monetary estimates are not billing or a hard spend cap.

Bare mode deliberately does not reuse Claude subscription login/keychain credentials. This adapter supports the CLI's documented API-key path only; it neither extracts OAuth stores nor claims subscription compatibility. The existing Codex adapter's supported authentication-home path remains available, so direct API billing is not a requirement of Watchhouse as a whole. Other Claude authentication modes need their own explicitly qualified adapter rather than relaxed flags.

Model authority is active independently per `(adapter, profile)` identity, with global consecutive immutable revision IDs. Legacy profiles omit the new fields and retain their previous serialized digest shape (`codex/default`). Revising a profile invalidates that profile's work/admission; installing a different profile does not invalidate a previously adopted author from another profile. Budgets, ownership, frozen repair context and uncertain resources remain shared across harnesses. An independent reviewer uses a fresh session and an independently assembled briefing, never an author's private transcript.

`model-profiles`, authenticated `GET /api/v1/model-profiles` and the web inspect profile provenance, currency, credential presence and native admission separately. Metadata installation or a CLI advertisement grants no execution authority. A new adapter/profile must pass its own current resource/protocol admission; it cannot inherit Codex's proof.

## Verification

A local no-account probe exercised the actual pinned Claude binary against synthetic loopback Anthropic Messages SSE. It observed one tool-free request and a completed matching JSON result. The retained sanitized JSONL fixture drives parser rejection tests. Cross-harness adoption/review/publication is tested using injected native-shaped observations; these are controller fixtures, not actual model output or live GitHub proof.

The native CI drill separately qualifies actual Claude with its own uniquely delegated cgroup. It measures empty advertised execution tools, sealed qualification-briefing forwarding, protocol completion, advancing-descendant cancellation, cleanup, coordinator-offline watchdog and delayed-start fencing. Its result is required on the implementing final head. Ordinary tests never invoke an account or model. Synthetic endpoint credentials are fixed inert markers and no real provider is contacted.

Live activation requires an explicitly authorized API key/model profile, qualified Linux worker and current proof. Actual authentication, account/model/billing behavior and real model proposals/reviews remain unverified. macOS/Windows native worker capability routing/cancellation is a separate M7 gate; coordinator package CI is not that proof.
