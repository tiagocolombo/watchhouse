# ADR 0040: Scope service-owner access to explicitly granted resources

Status: accepted implementation choice, 2026-11-21. Extends ADR 0039.

Add a distinct service_owner capability with OS-installed exact service/environment pairs and/or exact case IDs. Neither a case owner label nor impact prose, source tags, actor claims or a request body grants scope. Services come from controller-normalized source observations bound to installed source mappings; verify their retained digest before authorizing. Manual/unmapped cases require exact OS case grants. Empty, duplicate, wildcard-by-interpretation or misleading global-role restrictions grant nothing: names are literal exact values, and scoped grants belong only to service_owner. Existing global policy serialization and digests remain compatible.

Check case resources, evidence membership and cross-case mutation targets before dispatch. Restrict queue and evidence-membership SQL before the output limit, avoiding starvation behind unrelated global records. Preserve normal ownership, independent review, versions, receipts and execution/effect authority. Service owners cannot install configuration, use human/global administration or fake-worker endpoints, or create an unclassified manual case through global intake. Global operators own intake; OS operators explicitly grant manual cases. Scoped case commands and inspection remain available without global health/configuration access.

A grant authorizes the complete retained case and material already incorporated into it, including historical references and attributed prose. It does not grant dereference access to another case/evidence. Do not claim semantic redaction of copied prose, free text or artifacts. Remove automatic cross-scope correlation candidates/relations and global topology from scoped snapshots and qualification exports; render the export from that same filtered projection. Raw CLI/global views remain complete. Future features which automatically join incident data must preserve this scope boundary.

Recheck source scope alongside credential currency before every SSE batch; changed source mapping or OS revision closes future admission and streams. An already authorized request/batch can finish. No deployment, source freshness, recovery or native worker qualification is inferred from an access grant. The browser omits global requests/polling, shows only the scoped queue and retains usable attributed commands.

Rust fixtures exercise SQL limit placement, evidence/foreign target and global route denial, actual case mutation, normalized mapping drift, corrupted source denial, filtered correlation/export and legacy policy compatibility. The actual disposable localhost HTTPS browser fixture exercises a granted service owner's queue, denied unrelated case, hidden global controls and attributed rename. These are synthetic fixtures, not actual organization ownership, public ingress or live integrations. Independent remote-worker trust/native platform boundaries, retention/redaction and other M8 work remain required development.
